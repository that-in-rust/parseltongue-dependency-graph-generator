## PMF Definition For Us

This is **not** a general market score. This is a personal-agent-arsenal score.

The product-market-fit question is:

> Can we use this library or tool to help Codex explore a large codebase faster and more reliably, both as an agent-facing search surface and as a dependency/call graph that answers what calls what, what depends on what, and what context matters next?

High PMF means the tool helps with both sides:

- **Agent search:** find relevant code by symbol, concept, file, pattern, or natural-language-ish query.
- **Dependency/call graph clarity:** answer callers, callees, imports, exports, references, routes, impact, blast radius, changed symbols, or tests.
- **Large-codebase operation:** avoid full-repo reads, keep indexes current, and return bounded context.
- **Codex usefulness:** works as MCP, CLI, or simple local service that Codex can call.
- **Habit potential:** gives a repeated workflow, not a one-off demo.

## Scoring Rubric

| PMF | Meaning |
| ---: | --- |
| 90-100 | Install or benchmark first. Directly matches our agent-search plus dependency-graph job. |
| 80-89 | Strong candidate, but either narrower, less mature, or overlaps with a higher-ranked tool. |
| 70-79 | Useful as a secondary layer, specialized tool, or design reference. |
| 60-69 | Helpful substrate or adjacent workflow, but not enough alone for our PMF. |
| Below 60 | Good tool in its own category, but weak direct fit for our stated job. |

## Shreyas-Style Thesis

The winning surface is not "code search" and not "code graph" by itself.

The habit-forming job is:

> "Before Codex edits, ask a local tool what code matters, what calls it, what it calls, what breaks if it changes, and which tests or flows prove the edit is safe."

So the best tools are the ones with **job-shaped verbs**: `context`, `impact`, `trace`, `detect_changes`, `review_context`, `tests_for`, `call_graph`, `find_references`, `public/API impact`, and `repo_map`.

## Recommended Codex Arsenal

Start small. Tool sprawl will hurt Codex.

| Slot | Pick | Reason |
| --- | --- | --- |
| Primary graph brain | `GitNexus` for CRUD/API-heavy repos, or `codebase-memory-mcp` for huge mixed-language repos | These are the strongest answers to "what calls what and what matters next?" |
| Review/change safety | `code-review-graph` | Best bounded workflow for diff impact, review context, and agent-safe edits. |
| Search/discovery | `cocoindex-code` | Best low-friction semantic search when the agent does not know names. |
| Structural CLI sanity | `Clarity` | Fast file/module reachability, cycles, and before/after visual checks. |
| Benchmark challenger | `sdsrss/code-graph-mcp` or `Tessera` | Try if the primary graph brain misses route tracing, edit prep, tests, or hallucination validation. |

## Benchmark Before Committing To A Stack

Run each candidate on the same tasks:

| Task | Winning Signal |
| --- | --- |
| Find where a feature starts in an unfamiliar repo | Fewest calls, correct entry points, bounded context |
| Ask "who calls this?" for a non-trivial symbol | Correct direct and transitive callers, with evidence |
| Ask "what breaks if I edit this?" | Impact ranked by dependency strength, not a huge dump |
| Ask "which tests matter?" | Specific test files/commands with relationship evidence |
| Review a current git diff | Changed symbols, blast radius, risks, and next files to read |
| Validate a hallucinated symbol | Deterministic yes/no plus near matches |
| Trace CRUD route to DB | Route -> handler -> service -> repository/query/table/tests |
| Trace systems function through C/C++/Rust boundary | Header/export/module/call path, confidence clearly marked |

## Final Recommendation

For our stated PMF, the current best shortlist is:

1. `GitNexus`
2. `codebase-memory-mcp`
3. `code-review-graph`
4. `sdsrss/code-graph-mcp`
5. `Tessera`
6. `cocoindex-code`
7. `Clarity`

Use `GitNexus + code-review-graph + cocoindex-code + Clarity` as the first Codex setup.

Benchmark `codebase-memory-mcp`, `sdsrss/code-graph-mcp`, and `Tessera` against that setup before deciding whether to replace or add anything.
