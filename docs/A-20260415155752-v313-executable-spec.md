# Executable Spec: Parseltongue v313

**Date:** 2026-04-15  
**Source PRD:** [A-20260415152053-v313-PRD-L2.md](/Users/amuldotexe/Desktop/parseltongue-rust-LLM-companion/docs/A-20260415152053-v313-PRD-L2.md)  
**Scope:** Convert the v313 PRD into a behavioral and reliability-focused executable spec for the Rust-first Interface Dependency Map product.

---

## Feature Outcome

Parseltongue v313 is a Rust-first local **Interface Dependency Map** product with:

1. a Tauri control plane for workspace lifecycle, indexing, status, and URL handoff
2. a small six-endpoint HTTP surface for LLMs and CLI callers
3. a readable surfaced map for public dependency orientation and export

The product outcome is successful when a user can add a git repo, index it, obtain a local HTTP URL, search with `FFF`, inspect one-hop and two-hop interface impact, and export a readable Interface Dependency Map without raw code persistence.

## Actors And Boundaries

1. **Human desktop user**
   - adds a workspace
   - starts indexing or reindexing
   - sees status, freshness, and URL
   - views a lightweight graph preview in Tauri

2. **LLM or CLI caller**
   - calls the six HTTP endpoints
   - uses file-span hyperlinks for deeper reading
   - consumes one-hop, two-hop, and export packets

3. **Local Tauri control plane**
   - validates git roots
   - manages workspace lifecycle
   - manages progress and status display
   - applies least-privilege capability boundaries

4. **Local Rust-first indexing and walk subsystem**
   - parses Rust-first with tree-sitter only
   - maintains metadata and the surfaced Interface Dependency Map
   - does not claim compiler-truth semantics

## Failure Modes

1. non-git folder is accepted as a workspace
2. nested git repos are accidentally indexed into the parent workspace
3. workspace lifecycle states drift from persisted truth
4. preferred port is unavailable and the active URL is not refreshed
5. `FFF` search returns oversized or unhelpful packets
6. one-hop or two-hop endpoints return non-public-interface data
7. export includes imports or simple statements that should remain metadata-only
8. Tauri commands panic, block, or require broad filesystem permissions
9. forbidden HTTP endpoints or rank/cluster surfaces leak back into `v313`

## Performance And Reliability Limits

This first executable spec draft has **no hard latency SLOs**.

The limits in this draft are behavioral and reliability-focused:

1. no raw source persistence
2. no command-path panics in user-reachable Tauri flows
3. no broad filesystem capability scope by default
4. no extra LLM-facing HTTP endpoints beyond the frozen six-endpoint surface

## Language And Runtime Constraints

1. Rust-first
2. tree-sitter only
3. no raw source persistence
4. walk-runtime-only
5. Tauri 2 reliability posture
6. six HTTP endpoints only

## Public Interfaces Frozen By This Spec

The following public interfaces are frozen for `v313`:

1. The only LLM-facing HTTP endpoints are:
   - `GET /server-health-check-status`
   - `GET /codebase-statistics-overview-summary`
   - `GET /interface-dependency-search?q=...`
   - `GET /one-hop-impact-interface-list?entity=...`
   - `GET /two-hop-impact-interface-list?entity=...`
   - `GET /interface-dependency-map-export?format=json|csv`
2. The surfaced artifact name is **Interface Dependency Map**.
3. The default surfaced node types are `folder`, `file`, and `public_interface`.
4. The default surfaced edge types are `contains` and `depends_on`.
5. Tauri internal command names remain implementation-defined, but their reliability, async, error, progress, and permission contracts are fixed by this spec.

# Executable Requirements

### REQ-TAURI-001.0: Add Workspace Validates Git Root

**WHEN** a user adds a workspace through the Tauri layer  
**THEN** the system SHALL accept only a git repo root as a valid workspace  
**AND** SHALL reject a non-git folder without partial workspace registration  
**SHALL** return a serializable validation error for invalid workspace input

### REQ-TAURI-002.0: Nested Repos Are Detected And Excluded

**WHEN** a valid git repo root is scanned for workspace creation  
**THEN** the system SHALL detect nested git repos and submodules inside the selected root  
**AND** SHALL exclude them from parent indexing by default  
**SHALL** surface them as separately addable workspaces

### REQ-TAURI-003.0: Workspace Lifecycle States Use Persisted Truth

**WHEN** a workspace is created, indexed, reopened, or reindexed  
**THEN** the system SHALL derive `Invalid workspace`, `Nested repos detected`, `Unindexed`, `Indexing`, `Fresh`, `Stale`, and `Failed` from real persisted state  
**AND** SHALL refresh the displayed status after indexing and reindexing completes  
**SHALL** avoid leaving a successfully indexed workspace permanently marked `Unindexed`

### REQ-TAURI-004.0: Preferred Port And Active URL Are Managed Safely

**WHEN** a workspace finishes successful indexing  
**THEN** the system SHALL assign or reuse a preferred local port for that workspace  
**AND** SHALL expose the active HTTP URL in Tauri for copy-to-clipboard use  
**SHALL** bind to a safe fallback port and update the active URL when the preferred port is unavailable

### REQ-TAURI-005.0: Tauri Commands Follow Reliability Boundaries

**WHEN** a Tauri command performs I/O-heavy workspace, indexing, or port-management work  
**THEN** the command SHALL be async and use owned inputs  
**AND** SHALL return `Result<T, AppError>` or an equivalent serializable error shape on failure  
**SHALL NOT** use `unwrap()` or `expect()` in user-reachable command paths

### REQ-TAURI-006.0: Indexing Progress Uses Bounded Progress Channels

**WHEN** indexing or reindexing is running through Tauri  
**THEN** the system SHALL stream progress through channels or events with small serializable payloads  
**AND** SHALL avoid using events as a bulk transport layer  
**SHALL** keep command registration centralized

### REQ-TAURI-007.0: Tauri Permissions Stay Least-Privilege

**WHEN** the Tauri app declares capabilities and filesystem access  
**THEN** the system SHALL scope permissions by window label and least privilege  
**AND** SHALL scope filesystem access to exact required paths or patterns rather than broad access  
**SHALL** avoid granting unnecessary plugin or filesystem permissions to the main window

### REQ-WORKSPACE-001.0: One Workspace Equals One Git Root

**WHEN** a workspace is persisted  
**THEN** the system SHALL map that workspace to exactly one git repo root  
**AND** SHALL use that git root as the identity boundary for indexing and staleness evaluation  
**SHALL NOT** merge multiple git roots into a single workspace

### REQ-WORKSPACE-002.0: Staleness Is Surfaced Honestly

**WHEN** repo contents change after a successful index  
**THEN** the system SHALL surface the workspace as `Stale` based on real persisted state or reindex-required state  
**AND** SHALL preserve the last successful active URL until the next successful reindex completes  
**SHALL** avoid presenting stale data as fresh without an explicit state indicator

### REQ-API-001.0: Six Endpoint Surface Is Frozen

**WHEN** the v313 HTTP server is started  
**THEN** the system SHALL expose only the six frozen LLM-facing endpoints defined by this spec  
**AND** SHALL keep `server-health-check-status`, `codebase-statistics-overview-summary`, `interface-dependency-search`, `one-hop-impact-interface-list`, `two-hop-impact-interface-list`, and `interface-dependency-map-export` routable  
**SHALL NOT** expose interface-detail, rank, cluster, or mega-query endpoints as part of `v313`

### REQ-API-002.0: Search Is FFF-Driven And Packet-Shaped

**WHEN** a caller issues `GET /interface-dependency-search?q=...` with a valid non-empty query  
**THEN** the system SHALL execute `FFF` as the search front door and return a short candidate packet  
**AND** each candidate SHALL include interface key, label, kind, file path, line span, hyperlink-friendly file span, and lightweight aggregate counts  
**SHALL NOT** return a giant raw graph or raw source payload as the default search response

### REQ-API-003.0: Search Validation Errors Are Typed

**WHEN** `GET /interface-dependency-search?q=...` is called with a missing, empty, or invalid query  
**THEN** the system SHALL return a typed serializable validation error  
**AND** SHALL avoid panics or ambiguous empty-success responses  
**SHALL** preserve the frozen endpoint shape even on failure

### REQ-API-004.0: One-Hop Impact Returns Direct Public Interfaces Only

**WHEN** `GET /one-hop-impact-interface-list?entity=...` is called with a valid surfaced interface entity  
**THEN** the system SHALL return only the directly affected public interfaces one hop away  
**AND** SHALL keep the response scoped to public-interface results rather than internal metadata entities  
**SHALL** return a typed validation error when the entity is missing, invalid, or not resolvable to the surfaced map

### REQ-API-005.0: Two-Hop Impact Returns Bounded Public Interfaces Only

**WHEN** `GET /two-hop-impact-interface-list?entity=...` is called with a valid surfaced interface entity  
**THEN** the system SHALL return only the public interfaces reachable within two hops  
**AND** SHALL avoid returning deeper unbounded traversal data  
**SHALL** return a typed validation error when the entity is missing, invalid, or not resolvable to the surfaced map

### REQ-DATA-001.0: Metadata Layer Keeps Richer Internal Records

**WHEN** the Rust-first indexing pipeline persists workspace data  
**THEN** the SQL metadata layer SHALL contain workspaces, git roots, preferred ports, files, folders, Rust entities, imports, simple statements, comments, tests, counts, and spans  
**AND** SHALL support search shaping, file-span linking, local summaries, and future drill-down  
**SHALL** keep this richer metadata layer distinct from the default surfaced Interface Dependency Map

### REQ-DATA-002.0: Surfaced Interface Dependency Map Stays Readable

**WHEN** the default surfaced Interface Dependency Map is constructed for Tauri or API output  
**THEN** it SHALL include only `folder`, `file`, and `public_interface` nodes by default  
**AND** SHALL include only `contains` and `depends_on` edges by default  
**SHALL** exclude imports and simple statements from the default surfaced map

### REQ-EXPORT-001.0: JSON Export Shape Is Stable

**WHEN** `GET /interface-dependency-map-export?format=json` is called  
**THEN** the system SHALL return a readable JSON export with `workspace`, `nodes`, and `edges` top-level fields  
**AND** node rows SHALL be shaped for human or LLM consumption rather than internal storage optimization  
**SHALL** keep the export consistent with the default surfaced Interface Dependency Map

### REQ-EXPORT-002.0: CSV Export Emits Two Readable Tables

**WHEN** `GET /interface-dependency-map-export?format=csv` is called  
**THEN** the system SHALL emit `interface_nodes.csv` and `interface_edges.csv` as the CSV export surface  
**AND** the CSV output SHALL behave like a readable node table plus edge table  
**SHALL** keep the CSV content aligned with the surfaced map rather than the richer metadata layer

### REQ-EXPORT-003.0: Default Export Excludes Metadata-Only Nodes

**WHEN** any default `v313` Interface Dependency Map export is produced  
**THEN** the system SHALL exclude imports and simple statements from the default exported node set  
**AND** SHALL exclude edges that exist only to support metadata-layer records  
**SHALL** preserve the readability boundary between surfaced map and internal metadata

### REQ-TRUST-001.0: Raw Source Code Is Not Persisted

**WHEN** indexing, metadata persistence, or export is performed  
**THEN** the system SHALL persist derived structure, metadata, paths, counts, and spans only  
**AND** SHALL avoid persisting raw source code as part of the default product behavior  
**SHALL** keep file-span hyperlinks as the mechanism for deeper reading rather than stored source blobs

### REQ-TRUST-002.0: v313 Does Not Claim Compiler Or Rank Truth

**WHEN** the v313 product is queried or exported  
**THEN** the system SHALL remain Rust-first, tree-sitter-only, and walk-runtime-only  
**AND** SHALL NOT claim compiler-truth semantics, rank-runtime behavior, or cluster/community intelligence as part of `v313`  
**SHALL** keep interface-detail, rank, cluster, and mega-query surfaces out of the shipping `v313` interface
