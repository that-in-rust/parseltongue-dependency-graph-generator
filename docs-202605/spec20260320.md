# Executable Spec: Complete Parseltongue v300

**Date:** 2026-03-20  
**Source PRD:** [PRD-v300.md](/Users/amuldotexe/Desktop/parseltongue-rust-LLM-companion/PRD-v300.md)  
**Scope:** Finish the remaining implementation work needed to make the v300 PRD true in code, runtime behavior, and test coverage.

## Feature Outcome

Complete the current v300 implementation so that Parseltongue works as the PRD describes:

1. local Turso/libSQL-backed codebase indexing
2. CPU-only multi-signal search
3. graph-backed 7-event query journey over HTTP
4. Rust compiler enrichment for `.rs` files
5. Tauri workspace management for Mac

## Actors And Boundaries

1. **Human desktop user**
   - adds a workspace
   - runs ingestion
   - sees status and HTTP URL

2. **LLM or CLI caller**
   - calls HTTP endpoints
   - uses `/query?q=...` for the 7-event journey

3. **Rust compiler enrichment subsystem**
   - enriches Rust entities with compiler-derived facts
   - may require nightly + `rustc-dev`

4. **Boundaries**
   - v300 is CPU-only
   - storage is libSQL/Turso-compatible
   - non-Rust languages stay tree-sitter-level
   - Tauri is a lifecycle shell, not the place where search/graph logic lives

## Failure Modes

1. workspace builds on stable but `pt09-rustc-compiler-enrichment` fails on missing nightly/compiler components
2. `/query` exists in source but is not reachable in the product runtime
3. git-recency signal returns empty scores in normal repo execution
4. ingestion finishes but coverage is materially below PRD targets
5. Tauri workspace is registered but indexing/server lifecycle does not complete end-to-end
6. compiler enrichment crate exists but only stores placeholder values

## Performance And Reliability Limits

1. `GET /server-health-check-status` SHALL respond in `< 100 ms` on a warm local server
2. `GET /query?q=handle` phase-1 response SHALL complete in `< 200 ms` on this repo on a warm local database
3. `GET /query?q=handle&cluster=0` phase-2 response SHALL complete in `< 800 ms` on a warm local database
4. ingestion of this repo SHALL complete without panic
5. all non-`pt09` workspace crates SHALL pass tests on stable
6. `pt09` SHALL either:
   - pass on pinned nightly with required components, or
   - fail with an explicit actionable validation error before enrichment starts

## Language And Runtime Constraints

1. Rust 2021 workspace
2. local libSQL/Turso-compatible storage
3. tree-sitter-based multi-language parsing
4. nightly-only `rustc_private` permitted for `pt09`
5. new generated names should follow 4-word naming where compatibility allows

# Executable Requirements

### REQ-V300-001.0: Stable Workspace Build Boundary

**WHEN** a contributor runs the workspace test suite on stable Rust
**THEN** the system SHALL pass all tests for `parseltongue-core`, `pt01-codebase-ingestion-engine`, `pt08-http-query-api-server`, `pt10-tauri-workspace-manager`, and `parseltongue`
**AND** SHALL exclude or gate `pt09-rustc-compiler-enrichment` behind an explicit nightly/toolchain check
**SHALL** emit an actionable error message for missing `rustc-dev`, `rust-src`, or nightly requirements

### REQ-V300-002.0: Git Recency Signal Works On Real Repo

**WHEN** the search layer computes git-recency scores inside the current repository
**THEN** the system SHALL return a non-empty score map for tracked files
**AND** SHALL return only scores in the range `(0.0, 1.0]`
**SHALL** return an empty map without panic when the path is not a git repository

### REQ-V300-003.0: Journey Endpoint Is Routable

**WHEN** the HTTP server starts from the current v300 codebase
**THEN** the system SHALL register `GET /query`
**AND** SHALL return a structured JSON response for phase 1 when `q` is present
**SHALL** return a typed validation error when `q` is missing or empty

### REQ-V300-004.0: Journey Phase 1 Produces Candidate Clusters

**WHEN** `GET /query?q=<term>` is called against an indexed codebase
**THEN** the system SHALL preprocess the query and run FTS + symbol trie + trigram + git-recency RRF fusion
**AND** SHALL choose an anchor and derive at least one cluster summary when matching entities exist
**SHALL** return `phase = "no_results"` when no matches exist after preprocessing

### REQ-V300-005.0: Journey Phase 2 Returns Deep Context

**WHEN** `GET /query?q=<term>&cluster=<n>` is called with a valid cluster index
**THEN** the system SHALL return entity snippets for the selected cluster
**AND** SHALL include the selected anchor and entity count
**SHALL** return a typed range error when the cluster index is out of bounds

### REQ-V300-006.0: Public Anchor Traversal Is Deterministic

**WHEN** the top search hit is private or non-public
**THEN** the system SHALL walk the graph breadth-first to find the nearest visible/public anchor
**AND** SHALL return the original entity when no public ancestor is reachable
**SHALL** produce deterministic output for the same graph state and query input

### REQ-V300-007.0: Ego Cluster Budgeting Is Enforced

**WHEN** a cluster is built around an anchor with a token budget
**THEN** the system SHALL always include the anchor
**AND** SHALL prefer callers before callees when truncating to budget
**SHALL** keep reported `estimated_tokens` less than or equal to the requested budget except for the mandatory anchor inclusion case

### REQ-V300-008.0: Rust Compiler Enrichment Produces Real Facts

**WHEN** `pt09-rustc-compiler-enrichment` runs on a compilable Rust project under pinned nightly
**THEN** the system SHALL populate `rustc_scope` for matched entities
**AND** SHALL populate at least these non-placeholder fields for supported Rust items: `rustc_sig`, `visibility`, and one of `mir_calls` or `trait_impls`
**SHALL** avoid storing placeholder-only enrichment rows for successfully analyzed items

### REQ-V300-009.0: MIR Call Extraction Is Implemented

**WHEN** a Rust function has callable MIR terminators
**THEN** the system SHALL extract concrete callee identifiers from MIR
**AND** SHALL serialize those callees into enrichment output or downstream entity rows
**SHALL** return an empty list only when no call targets exist or MIR is unavailable

### REQ-V300-010.0: Tauri Workspace Lifecycle Works End-To-End

**WHEN** a user adds a workspace through the Tauri layer
**THEN** the system SHALL create a `.parseltongue` workspace directory and DB path
**AND** SHALL persist workspace metadata across restarts
**SHALL** support start/stop of one HTTP server per workspace

### REQ-V300-011.0: Tauri Workspace Status Is Refreshed

**WHEN** a workspace is indexed or re-opened
**THEN** the system SHALL update `entity_count`, `edge_count`, and `last_indexed_at`
**AND** SHALL compute `Fresh`, `Stale`, or `Unindexed` from real persisted state
**SHALL** avoid leaving newly indexed workspaces permanently marked `Unindexed`

### REQ-V300-012.0: Ingestion Pipeline Completes On This Repo

**WHEN** the v300 ingestion pipeline runs on this repository
**THEN** the system SHALL finish without panic and persist entities and edges into libSQL/Turso storage
**AND** SHALL make the resulting codebase queryable by PT08
**SHALL** record ingestion errors in a durable report when individual files fail

### REQ-V300-013.0: Coverage Reporting Is Honest

**WHEN** coverage statistics are generated for an indexed codebase
**THEN** the system SHALL distinguish parsed files, eligible files, ignored files, and failed files
**AND** SHALL avoid reporting current source files as "unparsed" without a corresponding recorded ingestion failure
**SHALL** expose enough detail for a contributor to identify the top missing coverage buckets

### REQ-V300-014.0: v300 Core Product Smoke Test Passes

**WHEN** a contributor follows the documented happy path on this repository
**THEN** the system SHALL support:
1. add workspace
2. ingest workspace
3. start HTTP server
4. call health/stats
5. call `/query?q=handle`
6. call `/query?q=handle&cluster=0`
**AND** SHALL produce successful responses for each step
**SHALL** complete this flow with no manual database surgery

### REQ-V300-015.0: Placeholder Debt Is Eliminated In Shipping Paths

**WHEN** the v300 completion branch is prepared for release
**THEN** the system SHALL contain no `TODO`, `STUB`, `PLACEHOLDER`, `todo!`, or `unimplemented!` in shipping code paths for the implemented v300 surface
**AND** SHALL replace temporary placeholder functions in the rustc enrichment path with working implementations or explicit unsupported-path errors
**SHALL** keep archived or intentionally out-of-scope code outside the shipping path
